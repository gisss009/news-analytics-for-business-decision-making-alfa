# Сводка для решений — новостная аналитика для принятия бизнес-решений

Прототип для кейса Альфа-Банка (Альфа Хак 2026, Changellenge). Сервис для руководителей крупного бизнеса
(собственник, CEO, финансовый директор, главный бухгалтер, казначей) внутри интернет-банка Альфа-Бизнес.

Пользователь выбирает компанию и получает не ленту новостей, а события, которые важны именно ей:
отбор идёт по отрасли, кредитам, выручке, ВЭД, поставкам и региону. Каждое событие разобрано по шести вопросам:

1. что произошло и откуда это известно;
2. почему это касается кредитов, выручки или поставок этой компании;
3. какие риски и возможности из этого следуют;
4. какой шаг уместен, если он следует из материалов;
5. как событие оценивает Альфа-Банк (цитата из его обзора, отдельно от вывода сервиса);
6. на каких источниках держится вывод (каждый открывается).

## Что в репозитории

| Часть | Папка | Что делает | Нужен ли ключ LLM |
|---|---|---|---|
| Сводка для пользователя | `web/` | основной интерфейс: главная, выбор компании, события компании, разбор события, другой срез, новости, вход | нет |
| Парсер материалов | `parser/` | собирает обзоры Альфа-Банка (PDF) и деловые новости (pyfinews) в карточки `data/out/*.json`; темы ставятся правилами, без модели | нет |
| Аналитическое ядро | `backend/` | FastAPI: профиль компании, лента, агентный цикл Planner → инструменты → Ranker → позиция банка → Interpreter → Verifier, метки «Факт / Аналитика банка / Вывод ИИ», ссылки на первоисточники | только в режиме с моделью |
| Интерфейс ядра | `frontend/` | React-клиент к backend: лента компании с «почему в вашей ленте», разбор события с метками и самопроверкой | — |
| Макет | `maket/` | статичный HTML-макет точки входа и сценария | нет |
| Скрипты запуска | `scripts/` | `dev.py` (ядро + `frontend/`), `web.py` (сводка `web/`), `fetch_data.py`, `ocr.py`, `node.py` | — |
| Данные | `data/` | синтетические компании, офлайн-набор новостей, ручные тезисы банка; сюда же скачиваются PDF кейса | — |

## Что нужно установить

| Что | Зачем | Обязательно |
|---|---|---|
| Python 3.11 или новее | backend, парсер, скрипты запуска | да |
| Docker Desktop (запущен, статус Running) | Node.js для интерфейсов и OCR работают в контейнерах | да |
| Интернет | свежие новости, первая загрузка npm-пакетов и образов Docker, PDF кейса | для первого запуска и режимов с живыми новостями |
| Ключ LLM в `.env` | разбор событий моделью | только для `--real` |

Node.js и Tesseract на машину ставить не нужно. Все команды ниже запускаются из корня репозитория и одинаково
работают на Windows, macOS и Linux (на macOS и Linux вместо `python` может понадобиться `python3`).

## Быстрый старт

```bash
git clone https://github.com/gisss009/news-analytics-for-business-decision-making-alfa.git
cd news-analytics-for-business-decision-making-alfa
```

Всё сразу одной командой Docker (сводка, ядро, API; без ключа LLM):

```bash
docker compose up
```

Через 2–4 минуты (первый запуск ставит зависимости и собирает выгрузку): сводка — http://localhost:5174,
интерфейс ядра — http://localhost:5173, API — http://localhost:8000/docs. Остановка — Ctrl+C,
затем `docker compose down`. Режим с моделью: `LLM_MODE=real` и ключ в `.env`, затем `docker compose up`.

Или по частям, скриптами с флагами (подробно — ниже). Сводка для пользователя (`web/`) — откроется
http://localhost:5174:

```bash
python scripts/web.py
```

Аналитическое ядро с интерфейсом `frontend/` без ключа LLM — откроется http://localhost:5173:

```bash
python scripts/dev.py
```

Остановка любой команды — Ctrl+C. Обе можно запустить одновременно в двух терминалах: порты не пересекаются.

## Все варианты запуска

### 1. Сводка `web/` — `scripts/web.py`

| Команда | Что происходит | Что нужно | Время |
|---|---|---|---|
| `python scripts/web.py` | если выгрузки `data/out` нет — собирает её (обзоры банка + свежие новости), затем запускает сводку | сеть при первом запуске | первый раз 2–4 мин, дальше ~10 с |
| `python scripts/web.py --refresh` | пересобирает выгрузку со свежими новостями | сеть | 1–3 мин |
| `python scripts/web.py --no-news` | выгрузка только из обзоров банка, без интернета | PDF кейса в `data/analytics` | ~10 с |
| `python scripts/web.py --no-browser` | не открывать браузер | — | — |

Что делает скрипт: создаёт `parser/.venv` с зависимостями парсера (`requirements.txt`), копирует PDF банка из
`data/analytics` в `data/alfa`, берёт их распознанный текст из кэша OCR (если кэша нет — распознаёт в Docker),
запускает парсер и Vite в контейнере `node:24-slim`. Ключ LLM и backend сводке не нужны.

Без PDF кейса сводка тоже работает, но события строятся только из новостей. Как скачать PDF — в разделе «Данные».

### 2. Аналитическое ядро и `frontend/` — `scripts/dev.py`

| Команда | Новости | Аналитика банка | Модель | Что нужно |
|---|---|---|---|---|
| `python scripts/dev.py` | офлайн-набор вымышленных новостей | тезисы из OCR PDF кейса, без PDF — ручные тезисы | нет (`LLM_MODE=stub`), ответы по шаблонам из фактов | ничего, кроме Docker |
| `python scripts/dev.py --live` | свежие деловые новости (Google News RSS через pyfinews, тексты через trafilatura) | как выше | нет | сеть; загрузка ~3 мин |
| `python scripts/dev.py --real` | как в выбранном режиме | как выше | разбор события пишет и проверяет модель | `LLM_BASE_URL`, `LLM_API_KEY` в `.env` |
| `python scripts/dev.py --real-ingest` | как в выбранном режиме | как выше | модель ещё и при подготовке данных (темы новостей, формулировки тезисов) | то же; первый запуск дольше на 15–20 мин |
| `python scripts/dev.py --no-browser` | — | — | — | не открывать браузер |

Флаги сочетаются. Самый полный режим — свежие новости и модель:

```bash
python scripts/dev.py --live --real
```

Что делает скрипт: создаёт `backend/.venv` (первый раз), распознаёт PDF кейса в Docker (первый раз ~3 мин),
загружает синтетические компании, готовит новости и тезисы банка, поднимает backend на http://127.0.0.1:8000
и `frontend/` на http://localhost:5173. Документация API — http://127.0.0.1:8000/docs.

В режиме `--real` первое открытие события занимает 30–90 с (модель пишет блоки, Verifier проверяет ссылки
и числа, при ошибке блок переписывается). Повторное открытие — из кэша, мгновенно.

### 3. Всё сразу

Два терминала:

```bash
python scripts/dev.py --live --real
```

```bash
python scripts/web.py --refresh
```

Получится: сводка на http://localhost:5174, ядро и его интерфейс на http://localhost:5173, API на
http://127.0.0.1:8000/docs.

### 4. Части по отдельности

Только парсер, без интерфейса (результат — `data/out/materials.json`, `data/out/report.json`):

```bash
python -m pip install -r requirements.txt
python -m parser
python -m parser._pull_business
```

`python -m parser --no-news` — только обзоры банка. Обзоры кейса — это слайды без текстового слоя: парсеру нужен
либо кэш `data/alfa/.ocr` (его готовит `scripts/web.py`), либо установленный Tesseract с языками `rus` и `eng`.

Только backend API (после первого `scripts/dev.py`, из папки `backend`):

```bash
cd backend
.venv/Scripts/python -m uvicorn app.api.main:app --port 8000
```

На macOS и Linux путь к Python — `.venv/bin/python`.

Макет `maket/` — статичная страница, ей нужен любой веб-сервер из корня репозитория:

```bash
python -m http.server 8080
```

Затем открыть http://localhost:8080/maket/. Новости макет берёт из `data/out` (сначала соберите выгрузку).

## Настройка модели (`.env`)

```bash
cp .env.example .env
```

| Переменная | Значение |
|---|---|
| `LLM_MODE` | `stub` (по умолчанию) или `real`; скрипты выставляют сами по флагам `--real` и `--real-ingest` |
| `LLM_BASE_URL` | OpenAI-совместимый эндпоинт общего ключа кейса |
| `LLM_API_KEY` | ключ; файл `.env` в git не попадает |
| `DAILY_BUDGET_RUB` | дневной лимит, по умолчанию 500 ₽; при 80% — предупреждение, при 100% — отказ и шаблонный ответ |
| `MAX_VERIFY_ITERATIONS` | сколько раз Verifier может вернуть разбор на исправление, по умолчанию 2 |
| `DATASET_FOLDER_URL`, `ANALYTICS_FOLDER_URL` | ссылки на папки кейса для `scripts/fetch_data.py` |

Используются только 6 моделей из условий кейса: Gemma 4 26B A4B, GLM-5.3-Flash, Qwen3.6 35B A3B,
DeepSeek-V4.1-Flash, Qwen3-VL-30B-A3B-Instruct, Kimi-K2.6. Какая модель на каком шаге —
`backend/app/core/model_routing.yaml`. Все вызовы идут через один клиент `backend/app/llm/client.py`
с белым списком моделей, бюджетом и кэшем ответов.

## Сценарий демонстрации

Сводка `web/` (http://localhost:5174):

1. «Разобрать событие» → выбрать компанию, например «Дом торговли» (ритейл, товарный запас в кредит).
2. Список событий: у каждого — почему оно касается компании и есть ли практический шаг.
3. Открыть событие: материалы («Открыть материал» ведёт на новость или PDF банка), почему это важно, риски и
   возможности, уместный шаг, оценка банка, на чём основан вывод, как собран разбор.
4. Внизу — «Уточнить или взять другой срез»: ставка, курс, нефть, спрос, сталь, зерно.
5. Вернуться и выбрать другую компанию, например «Северный прокат», — список событий будет другим.
6. «Новости» — общая деловая лента. «Войти» — демонстрационный вход: подходит любой логин от 3 символов
   и пароль от 4, данные никуда не отправляются.

Ядро и `frontend/` (http://localhost:5173): «Открыть сервис» → компания (ленты «СтройИнвест Девелопмент» и
«Сибирское Золото» заметно различаются) → событие → метки «Факт», «Аналитика Альфа-Банка», «Вывод ИИ» у каждого
утверждения, блок «Самопроверка»; ссылка у утверждения открывает первоисточник.

## Если что-то не запускается

| Симптом | Что сделать |
|---|---|
| «Docker не отвечает» | запустить Docker Desktop и дождаться статуса Running |
| Порт занят | остановить прошлый запуск: Ctrl+C или `docker stop news-analytics-web news-analytics-frontend` |
| В сводке «Нет файла выгрузки» | запустить `python scripts/web.py --refresh` |
| В сводке нет обзоров банка | скачать PDF: `python scripts/fetch_data.py`, затем `python scripts/web.py --refresh` |
| `--live` загрузил мало новостей | источники временно недоступны; если живых новостей нет совсем, остаётся офлайн-набор |
| Событие в `--real` открывается долго | первое открытие 30–90 с — это нормально, дальше из кэша |
| Ответ «по шаблону» в `--real` | ключ не задан, модель недоступна или исчерпан дневной бюджет; сервис переходит на шаблонный ответ |

## Как соблюдены ограничения кейса

- Только 6 разрешённых моделей, все вызовы через `backend/app/llm/client.py`; дневной бюджет и кэш.
- Агентная логика написана сами, без LangChain, LangGraph, CrewAI и подобных фреймворков.
- Не пересказ: разбор строится по признакам компании; позиция банка показана отдельно от вывода сервиса.
- У каждого утверждения ядра есть метка (`fact`, `bank_analytics`, `model_inference`) и ссылки на источники;
  вывод без источника не отдаётся.
- Тексты новостей — данные, а не инструкции для модели; инструменты агентов только читают; вызовы журналируются.
- Ключ только в `.env`; реальные данные клиентов и материалы банка в репозиторий не попадают.

## Заглушки прототипа

- **Клиенты.** Только синтетические компании. В сводке `web/` — четыре вымышленные компании из `maket/scenario.js`,
  в ядре — 155 синтетических компаний из `data/synthetic`.
- **Модель.** Без ключа (`stub`) ответы детерминированные: тексты блоков по шаблонам из фактов, признаков и
  тезисов банка. Контракт тот же, что у модели. Сводка `web/` модель не использует: её разбор собирается правилами.
- **Новости.** По умолчанию в ядре — офлайн-набор вымышленных новостей, чтобы демо работало без сети; живые — `--live`.
- **Вход.** В сводке вход демонстрационный, без сервера и проверки пароля.
